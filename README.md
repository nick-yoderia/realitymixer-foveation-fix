# Reality Mixer foveation fix

Fixes [Reality Mixer](https://store.steampowered.com/app/1844610/) boxes
fading out under SteamVR 2.19's foveated streaming (Steam Link, e.g. on the
Steam Frame): the boxes only show inside the sharp, eye-tracked area and fade
away everywhere else. Setting SteamVR's stream quality to *Legacy* also hides
the problem, at the cost of the new stream; this fix keeps the new stream.

## Install

From the [latest release](../../releases), unzip and double-click
**Install.cmd**. It finds Reality Mixer in your Steam libraries, closes it if
it is running, swaps in the fix and starts Reality Mixer again.
**Uninstall.cmd** puts the original back.

A Reality Mixer update, or Steam's *Verify integrity of game files*, restores
the original DLL. If the boxes start fading again, run Install.cmd again.

## What's wrong, and what the fix does

Reality Mixer gives SteamVR a blank texture for each box face, then asks
SteamVR for its own copy of that texture (`GetOverlayTexture`) and paints the
box straight into it, but only into the full-size image. SteamVR makes the
smaller copies a texture needs when drawn at low resolution (its *mip levels*)
only when a texture is submitted, while it was still blank. The new foveated
stream draws everything outside the sharp area at low resolution, from those
blank mip levels, so the boxes fade out there.

The fix is an `openvr_api.dll` for Reality Mixer's folder. It forwards
everything to the original (renamed `openvr_api_real.dll`). Whenever Reality
Mixer calls SteamVR from the thread that created its boxes (at most every
250 ms; in practice every few seconds), it copies what Reality Mixer painted
into a texture of its own and submits that, so SteamVR rebuilds the mip levels
from the painted image. That copy lives on the fix's own Direct3D device, so it
never waits on Reality Mixer's device (re-submitting on Reality Mixer's device
froze it while editing boxes, in v0.1.0-alpha). A brand-new box can look faded for those few seconds.
Nothing else changes, and `RealityMixer.exe` is not modified. A short log goes to `%TEMP%\rmfix.log`.

The proper fix belongs in Reality Mixer: submit the texture again (or build
its mip levels) after painting it.

## Build

Needs Visual Studio 2022 Build Tools. The OpenVR 1.26.7 header that matches
Reality Mixer's interfaces (`IVROverlay_027`, `IVRSystem_022`) is included.

    powershell -File build.ps1           # -> build\openvr_api.dll
    powershell -File install.ps1         # installs build\openvr_api.dll
    sh tools/make-release.sh v0.1.0-alpha

`src/wrap_overlay.h` and `src/wrap_system.h` are generated by
`src/gen_wrap.py` from the header.
